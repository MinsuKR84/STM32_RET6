Controller Area Network 약자임
여러 제어 장치가 하나의 버스를 공유하면서 메시지를 주고받는 통신 방식임

자동차의 ECU 간 통신을 목적으로 개발되었으며, 현재는 자동차뿐 아니라 산업 자동화, 로봇, 엘리베이터, 모터 제어 등에서도 사용됨

CAN의 가장 큰 특징은 특정 장치 주소가 아니라 메시지 ID를 기준으로 통신한다는 점임

모든 노드는 버스에 전달되는 메시지를 확인하고, 필요한 ID의 메시지만 사용함



CAN 신호선
CAN은 차동 신호 방식으로 두 개의 신호선을 사용함, CAN_H, CAN_L

MCU의 CAN TX/RX 핀을 CAN_H와 CAN_L에 직접 연결할 수는 없음
반드시 CAN Transceiver가 필요함

```
STM32 CAN_TX ──┐
               │ CAN Transceiver ── CAN_H
STM32 CAN_RX ──┘                 └── CAN_L
```



차동 신호
CAN은 CAN_H와 CAN_L의 전압 차이를 이용하여 데이터를 표현함
두 선에 같은 방향으로 노이즈가 유입되더라도 전압 차이를 기준으로 판단하므로 노이즈에 강함

CAN에서는 비트 상태를 다음과 같이 구분함
Dominant : 우성 비트, 논리 0
Recessive : 열성 비트, 논리 1

여러 노드가 동시에 신호를 전송할 때 한 노드가 Dominant를 출력하면 버스 전체가 Dominant 상태가 됨
이 특성은 CAN 중재 과정에 사용됨



종단 저항
CAN 버스 양 끝에는 일반적으로 각각 120 Ω 종단 저항을 설치함
```
120 Ω                         120 Ω
CAN_H ───────────────────────── CAN_H
CAN_L ───────────────────────── CAN_L
```
전원이 꺼진 상태에서 CAN_H와 CAN_L 사이 저항을 측정하면 두 개의 120 Ω 저항이 병렬로 연결되므로 약 60 Ω이 측정됨
종단 저항은 신호 반사를 억제하고 통신 안정성을 높임



메시지 기반 통신
UART나 I2C에서는 특정 상대 장치와 직접 데이터를 주고받는 형태가 일반적임
반면 CAN에서는 데이터에 메시지 ID를 붙여 버스에 전송함
```
ID   : 0x123
DLC  : 4
Data : 10 20 30 40
```
각 노드는 필터를 이용하여 필요한 ID만 수신할 수 있음

예를 들어 다음과 같이 역할을 정할 수 있음

| CAN ID | 의미     |
| ------ | ------ |
| 0x100  | 모터 명령  |
| 0x101  | 모터 상태  |
| 0x300  | 센서 데이터 |
| 0x300  | 오류 상태  |
CAN ID 자체의 의미는 사용자가 통신 규약을 설계하여 정함



표준 ID와 확장 ID
CAN은 두 가지 ID 형식을 지원함

Standard ID
11-bit Identifier 
범위: 0x000 ~ 0x7FF

Extended ID
29-bit Identifier 
범위: 0x00000000 ~ 0x1FFFFFFF

간단한 프로젝트에서는 일반적으로 11비트 Standard ID를 많이 사용함



CAN 데이터 프레임
Classic CAN 데이터 프레임은 주요하게 다음 요소로 구성됨
SOF → Arbitration Field → Control Field → Data Field → CRC → ACK → EOF

SOF : 프레임의 시작을 나타냄
Arbitration Field : 메시지 ID와 프레임 형식 정보가 포함됨
Control Field : 데이터 길이를 나타내는 DLC 등이 포함됨
Data Field : 실제 데이터임, Classic CAN에서는 0~8바이트를 전송함
CRC : 전송 오류를 검출하기 위한 값임
ACK : 다른 노드가 프레임을 정상적으로 수신했음을 나타냄
EOF : 프레임의 끝을 나타냄

CAN FD는 Classic CAN과 달리 더 많은 데이터와 더 높은 데이터 구간 속도를 지원하지만, MCU와 트랜시버가 CAN FD를 지원해야 함



버스 중재
여러 노드가 동시에 CAN 메시지를 보내려 할 수 있음
CAN은 ID를 이용하여 충돌 없이 우선순위를 결정함
CAN에서는 ID 값이 작을수록 우선순위가 높음
 
예를 들어 다음 두 노드가 동시에 전송한다고 가정함
```
노드 A: ID 0x100
노드 B: ID 0x200
```
비트를 전송하면서 자신이 보낸 값과 실제 버스 값을 비교함

노드 B가 Recessive 비트를 전송했는데 버스에서 Dominant 비트가 확인되면, 더 높은 우선순위 메시지가 전송되고 있다고 판단하여 송신을 중단함

따라서 0x100 메시지가 먼저 전송되고, 0x200 메시지는 버스가 비었을 때 다시 전송함

이 과정에서 우선순위가 높은 프레임은 손상되지 않으므로 비파괴적 중재라고 함



CAN 비트 타이밍
CAN 통신 속도는 Peripheral Clock과 다음 설정값으로 결정됨
한 비트 시간은 여러 개의 Time Quantum으로 구성됨

Prescaler
Synchronization Jump Width
Time Segment 1
Time Segment 2

일반적인 계산 형태는 다음과 같음
```
CAN Baud Rate = CAN Peripheral Clock ÷ [Prescaler × (1 + BS1 + BS2)]
```

예를 들어 CAN 클록이 8 MHz이고 다음 설정을 사용하면
```
Prescaler = 4
BS1       = 13 TQ
BS2       = 2 TQ
```

전체 Time Quantum은 다음과 같음
```
1 + 13 + 2 = 16 TQ
```

따라서 Baud Rate는 다음과 같음
```
8 MHz ÷ (4 × 16) = 125 kbit/s
```
CAN 버스에 연결된 모든 노드는 동일한 Baud Rate를 사용해야 함



CAN 필터
CAN 버스에서는 모든 메시지가 모든 노드에 전달됨

STM32의 CAN 필터를 사용하면 필요한 ID의 메시지만 FIFO로 전달할 수 있음

예를 들어 STM32가 0x456 메시지만 처리하도록 필터를 설정할 수 있음

필터가 잘못 설정되면 메시지가 버스에 정상적으로 존재해도 수신 콜백이 실행되지 않을 수 있음

개발 초기에는 모든 메시지를 허용하는 필터로 통신을 확인한 뒤, 필요한 ID만 허용하도록 변경하는 것이 편리함



CAN의 장단점
장점
차동 신호를 사용하여 노이즈에 강함
여러 노드를 하나의 버스에 연결할 수 있음
CRC, ACK, 재전송 등 오류 처리 기능이 강력함
메시지 우선순위를 지원함
한 노드가 모든 장치를 직접 관리하지 않아도 됨
자동차와 산업 환경에 적합함

단점
CAN Transceiver가 별도로 필요함
비트 타이밍과 필터 설정이 비교적 복잡함
Classic CAN은 한 프레임에서 최대 8바이트만 전송함
종단 저항과 버스 구조를 정확하게 구성해야 함
데이터의 의미를 정의하는 상위 통신 규약이 별도로 필요함
