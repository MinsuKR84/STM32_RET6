# CAN 메시지 구조 추천

## Raspberry Pi → STM32

라즈베리파이는 버튼 입력이나 음성 명령을 해석해서 STM32로 명령을 보냅니다.

| CAN ID | 데이터    | 의미           |
| ------ | ------ | ------------ |
| 0x100  | `0x01` | 1층 이동        |
| 0x100  | `0x02` | 2층 이동        |
| 0x100  | `0x03` | 3층 이동        |
| 0x110  | `0x01` | 문 열기         |
| 0x111  | `0x01` | 문 닫기         |
| 0x120  | `0x01` | 수동 상승        |
| 0x121  | `0x01` | 수동 하강        |
| 0x130  | `0x01` | 정지           |
| 0x140  | `0x01` | 음성 명령 활성화 상태 |

예를 들어 STT가 “3층 가줘”를 인식하면:

```
Raspberry Pi STT 결과: "3층"→ CAN ID 0x100, DATA 0x03 전송→ STM32가 3층 이동 수행
```

---

## STM32 → Raspberry Pi

STM32는 현재층, 문 상태, 에러 상태를 계속 보냅니다.

|CAN ID|데이터|의미|
|---|---|---|
|0x200|`현재층`|1/2/3층|
|0x210|`상태값`|이동/정지/문상태|
|0x220|`리미트 상태 bitmask`|각 스위치 상태|
|0x230|`에러코드`|상한/하한/비상정지 등|
|0x240|`무게값`|로드셀 선택 시|

상태값 예시:

|값|상태|
|---|---|
|0|IDLE|
|1|MOVING_UP|
|2|MOVING_DOWN|
|3|ARRIVED|
|4|DOOR_OPENING|
|5|DOOR_CLOSING|
|6|DOOR_OPEN|
|7|DOOR_CLOSED|
|8|ERROR|

# 8. TTS/STT 동작 흐름

## 음성으로 층 이동

```
1. 사용자가 "2층 가줘" 말함2. Raspberry Pi STT가 "2층" 인식3. Raspberry Pi가 CAN으로 MOVE 2 전송4. STM32가 현재층 확인5. STM32가 메인 모터 구동6. 2층 리미트 스위치 감지7. STM32가 모터 정지8. STM32가 CAN으로 FLOOR 2 / ARRIVED 전송9. Raspberry Pi가 TTS로 "2층에 도착했습니다" 출력
```

---

## 음성으로 문 제어

```
"문 열어"→ Raspberry Pi STT→ CAN DOOR OPEN→ STM32가 TB6612FNG로 문 모터 구동→ 문 열림 리미트 감지→ STM32가 DOOR_OPEN 상태 전송→ Raspberry Pi TTS "문이 열렸습니다"
```

---

## 안전 상황

```
상한 리미트 감지→ STM32 즉시 모터 정지→ ERROR:UP_LIMIT CAN 전송→ Raspberry Pi TTS "상한 리미트가 감지되어 정지합니다"
```

안전 관련 판단은 라즈베리파이를 기다리지 말고 **STM32가 즉시 처리**해야 합니다.
